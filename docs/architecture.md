# Архитектура

## Windows

Electron main process выполняет SQL, файловые операции и запросы к OpenRouter. Renderer использует типизированный узкий IPC через preload. Входные данные валидируются Zod. Включены `contextIsolation`, sandbox и запрет произвольных новых окон. SQLite обновляется миграциями.

## Android

React работает в Capacitor WebView. Изменения сразу попадают в локальное хранилище; синхронизация выполняется в фоне. Нативный Java-плагин получает персональный AI-ключ текущего профиля и обращается к OpenRouter напрямую с устройства. Общие расчёты, схемы и промпты импортируются из соседнего `NEXUS/src/shared`.

## Синхронизация

Сервер хранит ревизию снимка, отдельные данные профилей и последние пять зашифрованных копий. SSE сообщает устройствам о новых ревизиях; повторное соединение имеет задержку и резервный режим. Клиент объединяет записи по идентификаторам и времени изменения, сохраняя незагруженные локальные изменения. При изменении одной записи побеждает более свежая версия.

HTTPS завершается в nginx; Python-служба слушает только localhost. Серверные настройки доступа лежат вне снимков данных. Приглашение не заменяет ключ управления OpenRouter и не даёт прав владельца.

## ИИ

Экономичный набор используется по умолчанию: Gemini 2.5 Flash Lite для разбора, DeepSeek V3.2 для наставника и карьерных задач, Whisper для речи. Владелец может включить ручной выбор. Структурированные ответы валидируются; пользователь проверяет предложения перед применением.

Ключи OpenRouter хранятся отдельно от пользовательских экспортов. Индивидуальные лимиты проверяет провайдер; стоимость некоторых ответов может остаться неизвестной. Техническая проверка ключа не доказывает доступность всех выбранных моделей из текущей сети.
