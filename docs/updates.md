# Обновления NEXUS

Начиная с Windows 0.4.9 и Android 0.2.10, приложение проверяет опубликованные стабильные релизы `CaptainReinor/nexus` через десять секунд после запуска и раз в шесть часов, пока открыто. Промежуточные коммиты, черновики и предварительные релизы не устанавливаются.

## Использование

Windows скачивает найденный установщик в фоне. Нажмите «Установить», когда готовы перезапустить приложение. Автоматической установки при выходе нет. Перед установкой сохраняются изменения из открытых редакторов и копия базы `before-update.sqlite`.

Android показывает доступное обновление. Нажмите «Скачать», затем «Установить» и подтвердите системную установку. При первом обновлении Android может предложить разрешить NEXUS устанавливать приложения. После выдачи разрешения нажмите «Установить» повторно. Проверяются контрольная сумма APK, имя пакета, новая версия и совпадение сертификата с установленным NEXUS. Копия сохранённых состояний создаётся в закрытой папке приложения перед установкой; данные остаются при обновлении поверх текущей версии.

В настройках есть ручная проверка. Если интернет недоступен, остальные функции продолжают работать. Первая версия с обновлениями устанавливается вручную из GitHub Releases. Linux в этом выпуске не обновлялся.

## Публикация следующего релиза

1. Повысить версии Windows и Android, а также `versionCode` Android. Сохранить прежний ключ подписи APK; смена подписи не позволит обновить установленное приложение.
2. Пройти проверки, собрать Windows NSIS и APK. В Windows использовать `--publish never` при сборке для отдельной проверенной публикации.
3. Создать **черновик** стабильного GitHub Release с тегом `v<версия Windows>` и точным коммитом.
4. Добавить EXE с именем из `latest.yml`, его `.blockmap`, APK с именем `NEXUS-<версия Android>.apk`, контрольные суммы и сгенерированный `latest.yml`. Не переименовывать EXE без изменения метаданных.
5. Проверить соответствие размеров и хешей. Для APK требуется поле GitHub `digest` со значением `sha256:…`, оно создаётся GitHub при загрузке файла.
6. Опубликовать релиз только после загрузки всех файлов и метаданных. Отметить его последним стабильным релизом. Само изменение исходников на GitHub обновление не запускает.

Репозиторий и доступ к публикации релизов являются доверенной точкой распространения. Контрольные суммы защищают от повреждения загрузки. Они не заменяют защиту аккаунта GitHub. Приватные ключи, токены и пользовательские базы в релиз не входят.
