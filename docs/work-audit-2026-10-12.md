# Раздел «Работа»: аудит 12.10.2026

## Повторный аудит: 0.7.8

| Проблема | Исправление |
| --- | --- |
| Ошибочную или дублирующуюся вакансию можно было только архивировать | Полное удаление на ПК и Android с подтверждением, очисткой истории, связей и результатов ИИ в одной транзакции на ПК. Опыт, кейсы и учёт стоимости запросов сохраняются |
| Защита создания вакансии полагалась на асинхронное обновление React; два быстрых submit могли уйти до отключения кнопки | Синхронный флаг запроса блокирует повторное сохранение |
| Статус или ответ ИИ с другого устройства мог прийти после удаления родительской вакансии | При синхронизации удаляются дочерние строки без родителя. Учтены метки удаления, проверен повторный обмен |
| Завершение ИИ-запроса после удаления давало внутреннюю ошибку внешнего ключа | Понятное сообщение об удалённой вакансии, ответ не сохраняется, стоимость учитывается |
| Список обрезался до 1000 вакансий, история — до 2000 событий; статистика считалась по усечённой истории | Ограничения убраны |
| Равное время изменения не давало явного порядка на ПК | Второй ключ сортировки — идентификатор записи, как на Android |

Повторно проверены IPC, автосохранение существующих вакансий, просмотр разбора до применения, формат работы, смена статусов и зависимости SQLite. 226 тестов проходят, в том числе отмена удаления, повторный submit, откат транзакции при ошибке и удаление во время ИИ-запроса. Источник уже имеющихся личных дублей по одному факту их наличия не установлен; автоматического удаления личных записей нет.

Проверка Android на физическом устройстве в этом аудите не выполняется; мобильные сценарии проверяются в браузере и сборкой APK. Платный запрос к модели не выполнялся.

## Исправлено в 0.7.7

| Проблема | Исправление |
| --- | --- |
| Промпт не определял формат работы; занятость и график могли попадать в это поле | Явно разделены место работы, занятость и график. Нормализуются офис, удалённо, гибрид и разъездной формат; условия и альтернативы сохраняются |
| На Windows и Android были разные инструкции и проверки ответа | Общий контракт разбора с JSON Schema, проверкой границ зарплаты, валюты и ссылок |
| Разобранные поля сразу попадали в редактор и автосохранение | Отдельный просмотр результата с выбором полей; применение только после действия пользователя |
| Запоздалый ответ мог затереть ручные правки или заполнить другую форму | Проверяются запрос, версия редактора и исходный текст. Каждое поле сравнивается с состоянием до запроса |
| Новая зарплата «от» могла объединяться со старой зарплатой «до» | Границы обновляются вместе, ручные изменения сохраняются. Неверный диапазон не проходит проверку при сохранении |
| Валюта распознавалась, но не редактировалась в форме Windows | Добавлено поле валюты |
| Обновление отсутствующей вакансии сообщало успех | Возвращается ошибка «Вакансия не найдена» |
| Android показывал не все распознанные поля, а структурированный ИИ-ответ мог выглядеть как JSON | По согласованному решению мобильный раздел ограничен просмотром и сменой статуса. Создание, опыт, редактирование и ИИ остаются на ПК |

## Проверка

- 218 автоматических тестов: формат работы, проверка ответа, ручные правки во время запроса, смена текста, зарплата и сохранение.
- Проверки TypeScript, ESLint, производственные сборки Windows и Android.
- Запуск упакованного Windows-приложения с изолированной базой.
- Проверка интерфейса Windows и мобильного интерфейса в браузере на вымышленных данных: применение выбранных полей, смена статуса, отсутствие горизонтального переполнения.
- Подпись APK совместима с предыдущим релизом.

Платные запросы к живой модели в этом аудите не выполнялись. Изменение промпта и проверка ответа снижают риск ошибок, но спорные поля всё равно предлагаются для просмотра до применения. Старые вакансии не переразбираются автоматически. Схема данных и сервер не меняются.
