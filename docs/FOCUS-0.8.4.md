# Фокус 0.8.4

## Личная база продуктов

Схема 15: focus_products, food_entries.product_id/nutrition_sources_json. Каталог скрыт от интерфейса и находится в профиле, входит в его синхронизацию/копии и разрешённый контекст фокуса. Перенос в основной NEXUS не передаёт каталог. История до границы фокуса не используется; новые записи без известной массы не обучают значения на 100 г. Домашние составные блюда без постоянного бренда не обучаются как неизменные продукты.

На 100 г хранятся калории, БЖУ, сахар, клетчатка, витамины с единицами и источники user/estimate по каждому полю. Имена и алиасы нормализуются; разные бренды, жирность и сырое/готовое состояние разделены. Технические ID для одинакового ключа стабильны на двух устройствах. Прежняя оценка не меняется от нового предположения модели; данные пользователя и явные исправления имеют приоритет. Для неизвестных показателей не подставляется ноль. Для новых маркированных продуктов без этикетки оценки не выдаются за данные производителя. Автоматического поиска в интернете нет.

В контекст выбирается до восьми подходящих продуктов; повторная запись может вернуть только ID и массу, а приложение рассчитывает нутриенты. Съеденная доля по-прежнему считается от исходного рецепта, каталог не уменьшается вместе с порцией. Старые записи обучают каталог один раз, а отпечатки связей корректируются только при доказанном соответствии старым полям, чтобы сохранить редактор истории.

## Дизайн

Выбор пользователя: типографика и мягкие карточки варианта «Бумага» на тёмном графитовом фоне. Изменения ограничены фокусом: спокойные поверхности, читабельный текст, светлый тёплый акцент, округлые элементы, плавные состояния кнопок и раскрытий, поддержка reduced motion. Основная тема не меняется. Вдохновение: организация обзора и подробностей Oura/Cronometer; чужие изображения и код не использованы.

- https://ouraring.com/blog/new-oura-app-experience/
- https://cronometer.com/blog/how-to-nutrition-report/

Проверки: 287 тестов приложения, 27 серверных тестов; 16 реальных сценариев Gemini на вымышленных данных (включая искусственно внесённую ошибку для проверки восстановления). Финальный живой набор стоил $0.132523. Перед этим тесты нашли отрицание новой этикетки и неоднозначность ID порции/продукта; оба случая исправлены и покрыты. Пустые необязательные поля трактуются как неизвестные, выдуманные непустые ID по-прежнему отклоняются. Проверены скрытые Windows/Android макеты, клавиатурный ввод, перезапуск настроек, отсутствие горизонтального переполнения и приватность относительно основной базы. Физический Android в этом прогоне не использовался.
