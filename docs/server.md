# Сервер NEXUS

Подходит Ubuntu с Python 3, systemd и существующим HTTPS-сайтом nginx. Служба слушает `127.0.0.1:18743`, nginx публикует `/nexus-api/`. Доступ к данным требует персонального Bearer-токена. Сервер может читать синхронизируемые данные; дополнительные резервные копии шифруются клиентом.

## Первая установка

1. Скачайте проверенную версию репозитория на VPS.
2. Проверьте `install_vps.py` и существующий nginx-сайт. Установщик рассчитан на конфигурацию с двумя строками `server_name <домен>;`; при отличии он остановится до изменений. Для другой структуры добавьте маршрут вручную после проверки.
3. Из корня репозитория выполните, подставив **свой** домен и путь:

```sh
sudo python3 install_vps.py --host nexus.example.com --nginx-site /etc/nginx/sites-available/nexus
```

Установщик сохраняет прежнюю конфигурацию nginx, проверяет её перед reload и откатывает при ошибке. Создаёт отдельную службу с DynamicUser, приватным каталогом состояния и токеном в `/etc/nexus-backup.env` с правами 0600. Этот файл и содержимое `/var/lib/nexus-backup` нельзя публиковать.

## Обновление существующей службы

Не запускайте установщик для каждого обновления. Выберите проверенный коммит на GitHub, скачайте из него обновляющий скрипт и укажите **тот же полный SHA**:

```sh
REV=ПОЛНЫЙ_SHA_КОММИТА
curl -fSL "https://raw.githubusercontent.com/CaptainReinor/nexus/$REV/deploy/update_server.py" -o /root/nexus-update.py
python3 /root/nexus-update.py --commit "$REV"
```

Скрипт загружает оба серверных модуля из одного коммита, проверяет Python, сохраняет предыдущий код и перезапускает только `nexus-backup.service`. При неудачной проверке `/health` восстанавливает старый код. Базу, настройки доступа, nginx и другие службы он не меняет. Копии кода сохраняются в `/opt/nexus-backup/code-backups`; это не копии личной базы.

GitHub Actions проверяет код, но не развёртывает его автоматически. Для постоянного автоматического развёртывания потребуется отдельный доступ с VPS к GitHub и ограниченный механизм деплоя; root-пароль и ключи не следует размещать в репозитории.

## Подключение устройств и друзей

На ПК владельца укажите HTTPS-адрес и токен сервера. Для приглашений подключите Management API Key OpenRouter в приложении. Другу передайте только его приглашение и адрес вашего сервера. У каждого друга отдельные данные и рабочий ключ OpenRouter с месячным лимитом; владельцу доступны управление и отзыв доступа.

Windows и Android подключаются к OpenRouter непосредственно с устройства. Доступность модели зависит от сети и правил провайдера. Секретная фраза нужна только для дополнительных зашифрованных копий; она не является кодом приглашения.
