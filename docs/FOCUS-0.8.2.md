# Фокус 0.8.2: надёжность питания

Схема 14 добавляет food_entries.meal_name, portion_fraction и portion_base_json. Исходный рецепт не теряется при указании доли. foodPortion задаёт абсолютную долю всех указанных ингредиентов, пересчитывая только известные значения. Нулевые значения отличаются от неизвестных. food с существующим ID исправляет полный ингредиент, сохраняя текущую долю; уточнения применяются до масштабирования. Разные блюда нельзя масштабировать одной операцией.

removeFood удаляет только существующую запись фокуса после явно выраженного запроса. Кнопка «Удалить» имеет подтверждение и проверяет updated_at; повторное удаление безопасно. Лишь legacy-записи с kcal=0, точной пометкой «Удалено по запросу пользователя.» и соответствующим сохранённым явным запросом удаляются при обновлении. Обычные нулевые продукты не затрагиваются.

Наставнику передаются только факты фокуса. savedReferences связывают прежние сообщения с текущими ID, prepared показывает исходный состав, manualFoodEdits фиксирует ручные отмены. Вопрос вместе с исправлением не отменяет действия. При неоднозначности модель уточняет спорную часть, сохраняя однозначную.

Одинаковый runFocusMentor для Windows/Android: строгая схема, проверка ссылок и пробное сохранение на копии. При структурной/семантической ошибке одна повторная попытка с точными ошибками; сетевые ошибки автоматически не повторяются. Перед каждой попыткой проверяется бюджет. Невалидный ответ не сохраняет факты.

Диагностика _focusDiagnostics в личном профиле: время, модель, ID запроса, этап, входной текст, неудачный ответ и ошибки с путями. Секреты скрываются; срок 30 дней, последние 20 событий, общий лимит 256 К символов. Журнал исключён из snapshot/контекста наставника и не публикуется в репозитории. Основная база получает данные фокуса только по прежней явной кнопке переноса.


Модель по умолчанию: google/gemini-3.8-flash, reasoning effort low. Проверено 13.10.2026: $0.75/M вход и $3.75/M выход, строгая JSON-схема поддерживается. На девяти сценариях с настоящим API, включая искусственно внесённый неверный ответ для проверки восстановления, стоимость успешного набора $0.065886; аналогичный Sonnet 4.6 — $0.394086. Это сравнение конкретного набора, не обещание постоянного коэффициента. Haiku 5.5 проверен по каталогу ($0.10/$0.50), но пробный запрос завершился сетевым тайм-аутом и не принят как рабочая замена. Прежний установленный по умолчанию Sonnet меняется на Gemini один раз; вручную заданная другая модель сохраняется.


Накопления только в фокусе: отдельный виртуальный счёт, пополнение/снятие, дневной график и прогресс к цели. saving сохраняется как перевод в focus_money, исключается из расходов/доходов; остаток больше не вычисляется по их разнице. Исправления и снятия не могут оставлять отрицательный дневной остаток. Ручные операции используют те же идемпотентные записи и редактор. Контекст наставника содержит отдельный savings. Основной NEXUS изменяется только после явного переноса; при нём счета переводов сопоставляются по назначению, а повторное нажатие не дублирует операции.

Проверки финального выпуска: 271 тест приложения, 26 серверных тестов; готовый Windows app.asar проверен через настоящий IPC и SQLite на вымышленной базе. Скрытые макеты Windows/Android проверены на отсутствие горизонтального переполнения и ручное пополнение. Финальный Gemini: 12 сценариев с настоящим API (13 запросов из-за искусственно внесённой ошибки), включая три сценария накоплений; все прошли, $0.090912. Физический Android в этом прогоне не использовался.
